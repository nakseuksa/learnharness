## 一、 测试工程全景概览

### 1.1 为什么单测是理解本系统的“金钥匙”？
在面向大模型（LLM）的多智能体复杂系统中，如果只通过 UI 界面调试，通常面临四大痛点：
1. **调用速度慢**：真实模型交互一次动辄几秒至十几秒；
2. **需要花钱**：每次试错都在消耗 Token 与 API 额度；
3. **输出不确定（Non-deterministic）**：大模型的回答具有随机性，难以稳定复现边界 Bug；
4. **链路太长**：从 Electron 窗口到 Next.js 路由，排查层级过深。

而 LearnHarness 建立了一套**100% 确定性、无网络依赖、毫秒级响应**的单测体系：
- 核心逻辑全部解耦为纯函数与端口适配器，测试时通过内存适配器注入；
- 大模型被替换为高度逼真的**剧本仿真器（`MockLanguageModelV4` / `scriptedEngine`）**；
- **阅读单测，就等于直接阅读作者对这套系统制定的最严密、最真实的“契约与规格说明书”**。

### 1.2 测试运行环境与原生驱动机制
系统基于 Node.js 原生的 `node:test` 测试套件，结合 `tsx` 进行 TypeScript 运行时转译：
```bash
# package.json 中的测试指令
NODE_ENV=test tsx --test tests/*.test.ts tests/*.test.tsx
```
单测文件分为两类：
- `*.test.ts`：纯 Node.js 服务端逻辑、领域模型、算法与流式测试；
- `*.test.tsx`：利用 React 服务端无头渲染（SSR）验证组件渲染与交互状态机。

## 四、 “单测反推学习法”四大实操秘籍

### 4.1 秘籍一：毫秒级单文件精准执行
系统使用的是 Node.js 原生测试体系，执行单个文件仅需 **1 ~ 2 秒**：
```bash
# 执行单个单测文件（以会话类型测试为例）
npx tsx --test tests/chat-kind.test.ts

# 执行核心对话主干单测
npx tsx --test tests/chat-flow.test.ts
```
> **优势**：不用启动繁重的前端和 Electron，立刻获得绿灯通过或红灯报错的极快反馈。

---

### 4.2 秘籍二：探针注入法（打 Log 观察真实入参与返回）
在源码中直接插入 `console.log`，然后运行单测，看控制台打印出什么：
```typescript
// 例如在 src/server/chat-handler.ts 的 handleChatInput 头部加上探针：
console.log("【探针】收到的真实输入:", JSON.stringify(input, null, 2));
console.log("【探针】当前会话历史条目数:", record.messages.length);
```
随后运行 `npx tsx --test tests/chat-flow.test.ts`，你会清清楚楚看到**抽象的 TypeScript 接口，在运行时究竟流淌着什么样的数据**！学习完直接 `git checkout` 撤销探针。

---

### 4.3 秘籍三：剧本逆向法（解读 `scriptedEngine` 数据契约）
在 AI 系统的开发中，最大的门槛是“大模型输出是随机的、还要花钱”。而作者在单测里设计了精妙的 **“剧本式模型”（Scripted Model）**：
打开 [tests/chat-flow.test.ts](file:///d:/0.default/learnharness/tests/chat-flow.test.ts)，看他是怎么写 Mock 的：
```typescript
// 作者在单测里预先写好了模型的剧本：
const engine = scriptedEngine([
  // 第 1 轮：模型说“你好，我们今天学二元一次方程”
  { text: "你好，我们今天学二元一次方程" },
  // 第 2 轮：模型发起了一个测验工具调用
  { toolCalls: [{ name: "quiz", args: { question: "x + y = 5, x = 2, 求 y", options: ["2", "3", "4"] } }] }
]);
```
> **逆向启示**：读这个 Mock 剧本，你就等于直接读到了**大模型与系统约定的数据契约协议**，比读任何文档都精准！

---

### 4.4 秘籍四：破坏性实验（故意改错看断言防御）
这是掌握核心逻辑最快的“黑客学习法”：
- 找到单测里的某一行 `assert.equal(chat.kind, "practice")`，故意改成 `assert.equal(chat.kind, "teach")`；
- 运行测试，看报错日志报出的 Diff 和堆栈轨迹；
- 或者在源码逻辑里故意把 `record.kind !== "practice"` 这行判断注释掉，看看哪些测试用例会当场爆红。
- **通过看“破坏了什么会报错”，你就能瞬间抓住这段业务代码不可替代的真正原因！**

## 五、 手把手实践：编写你的第一个实验单测（Scratch Test）

你可以在本地创建一个属于你自己的实验测试文件（例如 `tests/scratch-learn.test.ts`），亲手模拟一个会话流程：

```typescript
import { test, describe } from "node:test";
import assert from "node:assert/strict";
import { chatStore } from "../src/store/chats.ts";

describe("我的第一个 LearnHarness 学习单测", () => {
  test("验证创建一个会话并保存消息", () => {
    // 1. 创建一个新会话
    const chat = chatStore.createChat("我的测试教学会话");
    assert.ok(chat.id.startsWith("chat_"), "会话 ID 必须以 chat_ 开头");

    // 2. 模拟写入一条消息
    const myMessage = {
      id: "msg_1",
      role: "user" as const,
      content: [{ type: "text" as const, text: "你好，我想学勾股定理" }]
    };
    chatStore.saveMessages(chat.id, [myMessage]);

    // 3. 重新读取并断言
    const reloaded = chatStore.getChat(chat.id);
    assert.equal(reloaded?.messages.length, 1);
    assert.equal((reloaded?.messages[0].content[0] as { text: string }).text, "你好，我想学勾股定理");
    
    console.log("✔ 单测运行通过，会话持久化验证成功！");
  });
});
```

在终端运行它：
```bash
npx tsx --test tests/scratch-learn.test.ts
```
只需不到 1 秒，测试便会绿灯通过。通过这种零成本的动手实践，你将以极快速度融会贯通整套架构！
